Apprendre par cœur donne une performance parfaite sur ce qu'on a déjà vu, et ne transfère pas. En machine learning, cela s'appelle l'**overfitting** (sur-apprentissage). Le but d'un modèle n'est jamais de bien prédire ses données d'entraînement : c'est de bien prédire **des données qu'il n'a jamais vues**. C'est la **généralisation**.

## Train et test

Pour mesurer la généralisation, on met de côté une partie des données que le modèle ne verra jamais pendant l'entraînement : le **test set**. On compare alors :

- l'**erreur d'entraînement** (*training error*) : à quel point le modèle colle aux données qu'il a vues ;
- l'**erreur de test** : à quel point il prédit des données nouvelles. C'est la seule qui compte vraiment.

Ici, les données viennent d'une vraie fonction (en pointillés) à laquelle on ajoute du bruit. On essaie de la retrouver avec un polynôme, dont le **degré** règle la complexité : degré 1, une droite ; degré 15, une courbe capable de presque n'importe quelle forme.

Au début, plus de flexibilité aide le modèle à capter la vraie forme : les deux erreurs baissent. Puis le modèle commence à suivre **le bruit** des points d'entraînement : des zigzags qui n'existent pas dans la réalité. L'erreur d'entraînement continue de baisser, mais l'erreur de test remonte. Cette courbe en U est l'une des figures les plus importantes du machine learning.
</Predict>

## Le bias-variance tradeoff

L'erreur de test d'un modèle se décompose en trois morceaux :

$$
\mathbb{E}\big[(y - \hat f(x))^2\big] = \underbrace{\text{Biais}^2}_{\text{modèle trop simple}} + \underbrace{\text{Variance}}_{\text{modèle trop sensible}} + \underbrace{\sigma^2}_{\text{bruit irréductible}}
$$

- Le **biais** (*bias*) : l'erreur systématique d'un modèle trop rigide. Une droite ne pourra jamais suivre une vague, quelles que soient les données. C'est l'**underfitting**.
- La **variance** : à quel point le modèle change si on l'entraîne sur un autre jeu de données. Un modèle trop flexible apprend les particularités de *son* échantillon. C'est l'**overfitting**.
- Le **bruit** $\sigma^2$ : l'aléa des données elles-mêmes. Aucun modèle ne peut descendre en dessous.

Pour voir biais et variance séparément, il faut entraîner **plusieurs** modèles sur des jeux de données différents. Coche la case, puis compare un degré faible et un degré élevé.

<PolyFitLab id="ensemble" degree={1} panels={["fit"]} ensemble={true} />

<Callout type="intuition">
Degré faible : les 20 modèles se ressemblent tous (variance faible) mais ratent tous la vraie forme de la même façon (biais élevé). Degré élevé : en moyenne ils tombent juste (biais faible), mais chacun part dans tous les sens (variance élevée). Le meilleur modèle est un **compromis** entre les deux.
</Callout>

<PolyFitLab id="optimum" degree={1} challenge="bv-best" />

<Callout type="rappel">
L'**espérance** $\mathbb{E}[\cdot]$ est une moyenne « sur tous les jeux de données possibles ». Le biais compare la prédiction *moyenne* à la vérité ; la variance mesure la dispersion des prédictions autour de cette moyenne. Ce sont exactement le trait épais et les traits fins du labo ci-dessus.
</Callout>

<Exercise
  id="decomposition"
  question="Un modèle a un biais² de 0,04 et une variance de 0,10, sur des données dont le bruit vaut σ² = 0,09. Quelle erreur de test (MSE) peut-on attendre ?"
  answer={0.23}
  tolerance={0.002}
  hint="Additionne les trois composantes de la décomposition."
>
$\text{MSE} = 0{,}04 + 0{,}10 + 0{,}09 = 0{,}23$.

La variance est la plus grosse part réductible : le modèle est trop sensible à son échantillon. On peut viser plus de données, plus de régularisation ou un modèle plus simple. Le bruit (0,09) restera, quoi qu'on fasse.
</Exercise>

## Plus de données, moins de variance

Le bon degré n'est pas une constante : il dépend de la **quantité de données**. Un modèle complexe devient raisonnable s'il a assez d'exemples pour que le bruit se compense.

<PolyFitLab id="donnees" degree={12} controls={["degree", "n"]} challenge="bv-data" />

Les leviers contre l'overfitting, en résumé :

- **Plus de données** (le meilleur, quand c'est possible).
- **Un modèle plus simple** (moins de paramètres, moins de degrés de liberté).
- **La régularisation** : pénaliser les modèles trop « tordus » (L1, L2, dropout…), sujet d'une prochaine leçon.
- **L'early stopping** : arrêter l'entraînement avant que l'erreur de validation ne remonte.

<Callout type="entretien">
« Comment savoir si un modèle overfit ? » Erreur d'entraînement basse **et** erreur de validation nettement plus haute. S'il underfit, les deux erreurs sont hautes et proches. Et un écart qui se réduit quand on ajoute des données confirme un problème de variance.
</Callout>

<Callout type="piege">
Choisir le degré en regardant l'erreur de **test** revient à entraîner sur le test set : il cesse d'être une mesure honnête. En pratique, on choisit les hyperparamètres sur un **validation set** (ou par cross-validation) et on ne regarde le test set qu'une seule fois, à la toute fin.
</Callout>

## Les courbes d'apprentissage

Avant d'investir dans la collecte de données, une question pratique : **en ajouter va-t-il aider ?** Les courbes d'apprentissage y répondent. On entraîne le modèle sur des sous-ensembles de taille croissante et on trace l'erreur d'entraînement et l'erreur de validation.

<LearningCurves />

- **Biais élevé** : les deux courbes se rejoignent rapidement, toutes les deux **au-dessus** de l'objectif. Ajouter des données ne servira à rien ; il faut un modèle plus expressif ou de meilleures variables.
- **Variance élevée** : un grand écart entre les courbes, qui se réduit quand les données augmentent. Plus de données, ou plus de régularisation, vont aider.

<Callout type="astuce">
En scikit-learn, `learning_curve` trace ces courbes en une ligne avec validation croisée. C'est l'un des diagnostics les plus rentables d'un projet : il évite de passer des semaines à collecter des données pour un modèle limité par son biais.
</Callout>

## En entretien

<Interview q="Comment sais-tu si collecter plus de données va améliorer ton modèle ?">
Je trace une **courbe d'apprentissage** : erreur d'entraînement et de validation en fonction de la taille du jeu d'entraînement. Si un écart important se réduit encore au bout de la courbe, le modèle souffre de variance et plus de données aideront. Si les deux courbes ont déjà convergé à un niveau trop élevé, c'est un problème de biais : il faut des variables plus informatives ou un modèle plus expressif. Je compare aussi au niveau d'erreur humain ou à une baseline pour savoir ce qui est atteignable.
</Interview>

<Interview q="Les très grands réseaux de neurones devraient overfitter. Pourquoi généralisent-ils bien ?">
Le compromis biais-variance classique prédit une courbe en U. Avec des modèles très surparamétrés, on observe parfois un **double descent** : l'erreur de test remonte autour du point où le modèle peut tout interpoler, puis redescend quand on continue d'augmenter la taille. Parmi les nombreuses solutions qui interpolent les données, l'optimisation (SGD, initialisation) favorise des solutions « simples », une **régularisation implicite**, à laquelle s'ajoutent les régularisations explicites (weight decay, data augmentation, dropout). Le compromis biais-variance reste un excellent outil de diagnostic, mais « plus de paramètres = plus d'overfitting » n'est pas une loi.
</Interview>

<Recap>
- But du ML : bien prédire des données **nouvelles** (généralisation), pas les données d'entraînement.
- Erreur de test = biais² + variance + bruit irréductible.
- Underfitting : biais élevé, erreurs train et test hautes et proches.
- Overfitting : variance élevée, train basse, test nettement plus haute.
- Leviers contre la variance : données, régularisation, modèle plus simple, early stopping.
- Courbes d'apprentissage : savoir si plus de données aidera.
- Hyperparamètres choisis sur un validation set ; test set utilisé une seule fois.
</Recap>
