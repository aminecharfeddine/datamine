## Le test de McNemar

On compte les exemples où les modèles sont en désaccord : $b$ (A juste, B faux) et $c$ (A faux, B juste). Si les deux modèles se valent, chaque désaccord a une chance sur deux de pencher d'un côté ou de l'autre :

$$
z = \frac{c - b}{\sqrt{b + c}}
$$

suit approximativement une loi normale centrée réduite (on utilise souvent $\chi^2 = (|c - b| - 1)^2 / (b + c)$, avec une correction de continuité). Les cas d'accord, eux, n'interviennent pas.

<CompareLab id="mcnemar" challenge="paired-test" />

La différence d'accuracy est la même pour les deux tests ; c'est l'incertitude qui change. Le test non apparié inclut la variabilité due à la difficulté des exemples, commune aux deux modèles ; le test apparié la retire. Avec 800 exemples, il est déjà concluant, alors que le non apparié demande deux fois plus de données.

$20 / \sqrt{40} \approx 3{,}16$, bien au-delà de 1,96 : la différence est significative au seuil de 5 %, quels que soient les centaines d'exemples où les deux modèles sont d'accord.

## Pour n'importe quelle métrique : le bootstrap apparié

Pour un F1, une AUC ou un NDCG, il n'y a pas toujours de formule simple. Le **bootstrap apparié** rééchantillonne les exemples du test avec remise, calcule la métrique des deux modèles **sur le même échantillon**, et répète des milliers de fois pour obtenir la distribution de la différence.

```python
import numpy as np
from sklearn.metrics import f1_score

rng = np.random.default_rng(0)
n, diffs = len(y), []
for _ in range(2000):
    idx = rng.integers(0, n, n)
    diffs.append(f1_score(y[idx], pred_b[idx]) - f1_score(y[idx], pred_a[idx]))
print(np.percentile(diffs, [2.5, 97.5]))           # intervalle de confiance à 95 % de la différence
```

## Les autres sources de variance

- **La validation croisée** : les scores des plis ne sont pas indépendants (les jeux d'entraînement se recouvrent), et leur écart-type sous-estime l'incertitude. On compare les modèles pli par pli (test apparié sur les mêmes plis), avec prudence.
- **L'aléa de l'entraînement** : en deep learning, deux graines différentes donnent parfois des écarts aussi grands que la différence entre deux architectures. On entraîne plusieurs graines et on rapporte moyenne et dispersion.
- **Les comparaisons multiples** : tester 30 variantes et garder la meilleure produit un gagnant par hasard. On confirme sur un jeu de test intact.

<Callout type="intuition">
Comparer deux modèles sur le même jeu, c'est comme comparer deux coureurs sur le même parcours : le vent et les côtes touchent les deux. Ce qui compte, c'est l'écart entre eux, course par course, pas la variabilité de chaque temps.
</Callout>

<Callout type="piege">
Significatif ne veut pas dire utile. Sur 1 million d'exemples, un écart de 0,1 point sera significatif ; il ne justifiera pas forcément un modèle deux fois plus lent. Rapporte la différence avec son intervalle de confiance, et décide avec le coût, la latence et la maintenance.
</Callout>

<Callout type="entretien">
« Votre nouveau modèle fait +0,8 point d'AUC sur le test. Vous le déployez ? » Réponse structurée : vérifier que l'écart dépasse l'incertitude (bootstrap apparié, plusieurs graines), qu'il n'a pas été obtenu en choisissant parmi beaucoup de variantes sur ce même test, qu'il se retrouve par segment, et qu'il se traduit en valeur métier ; puis le confirmer en ligne par un test A/B.
</Callout>

## En entretien

<Interview q="Comment décides-tu qu'un modèle est significativement meilleur qu'un autre ?">
Je les évalue sur exactement les mêmes exemples, et j'utilise un test apparié : McNemar pour une accuracy, ou un bootstrap apparié pour n'importe quelle métrique (F1, AUC, NDCG), qui donne un intervalle de confiance de la différence. S'il y a de l'aléa d'entraînement, je répète sur plusieurs graines. Je fais attention aux comparaisons multiples : si l'on a choisi parmi beaucoup de variantes, je confirme sur un jeu de test intact. Enfin, je regarde si l'écart compte vraiment pour le métier et je le confirme en ligne.
</Interview>

<Interview q="Pourquoi l'écart-type des scores de validation croisée ne suffit-il pas à comparer deux modèles ?">
Les scores des plis ne sont pas indépendants, puisque les jeux d'entraînement se recouvrent largement : leur dispersion sous-estime l'incertitude réelle. Et comparer deux moyennes avec leurs écarts-types ignore que les deux modèles ont été évalués sur les mêmes plis. Il vaut mieux comparer pli par pli (différence par pli), avec des tests corrigés pour la dépendance, ou répéter la validation croisée avec différentes graines de découpage.
</Interview>

<Recap>
- Mêmes exemples pour les deux modèles → **test apparié**, beaucoup plus puissant.
- **McNemar** : $z = (c - b)/\sqrt{b + c}$, seulement les désaccords.
- **Bootstrap apparié** : mêmes indices pour les deux modèles, intervalle de la différence, toute métrique.
- Variabilité de la graine, plis dépendants, comparaisons multiples.
- Significatif ≠ utile : différence, intervalle, coût, puis test en ligne.
</Recap>
